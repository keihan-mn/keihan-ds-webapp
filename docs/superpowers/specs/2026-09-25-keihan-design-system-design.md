# 京阪工技社 デザインシステム 設計書（第1段：土台＋業務アプリ用）

- 作成日: 2026-09-25
- 持ち主: 企画部
- 参考: 会社HP https://keihankogisha.co.jp/ ／ 見本 `~/src/【smple】-workspace-ui-kit`

## 1. 目的と範囲

社内の人が AI（Claude Code）と一緒に**業務用ウェブアプリ**（管理画面・業務ツール）を作るときの土台を用意する。

- 構成は「共通の土台（色・フォント・ロゴ・言葉づかい）」＋「使い方ルール」の2層
- 今回作るのは **土台＋業務アプリ用ルール**。社外ページ（LP 等）用ルールは第2段で別途設計する
- 配布方法は **ひな形コピー方式**：このリポジトリ自体が動くひな形で、新アプリはコピーして始める
- やらないこと：DB 接続・認証・社外ページ用ルール・ダークモード

## 2. 技術構成（見本を踏襲）

Next.js 16 / React 19 / TypeScript strict / Tailwind CSS v4（`@theme` で CSS 変数）/ shadcn/ui（`base-nova` = `@base-ui/react` ベース）/ lucide-react / zod / Vitest

- TypeScript は strict。`any`・非null断定（`!`）は使わない（ESLint で error）
- 新しい UI 部品は shadcn/ui（base-nova レジストリ）から追加する
- アイコンは lucide-react のみ
- Tailwind CSS v4 のテーマ・カラーは `tailwind.config.js` ではなく CSS で定義する（値は `app/globals.css` の `:root`、クラスとの対応は `@theme inline`）
- 外から入る値（JSON データ・フォーム入力・API の入出力）は zod で検証する
- デプロイ先は Vercel（`next build` の標準構成）

## 4. 業務アプリ用ルール

- **端末**: PC 最優先、タブレット幅（768px〜）で崩れない。スマホは表示が壊れない程度
- **編集方式**: フォーム＋「保存」ボタンで確定。未保存のまま画面を離れようとしたら確認を出す（タブを閉じる・再読み込み・画面内リンク・「戻る」ボタン）
- **状態の色**: 受付＝情報（水色）、作業中＝メイン（青）、完了＝成功（緑）、遅延＝注意（黄）。赤は使わない
- **ロゴ**: 正式データ（SVG）を `public/brand/` に置いて使う。未配置の間は社名テキストを表示する

## 5. ひな形に入れる画面

見本データは「スキャニング・印刷の受注案件」。

1. **ダッシュボード**: 件数・金額の数字カード＋状態別グラフ
2. **一覧**: 表＋キーワード検索＋状態の絞り込み。0件時の空状態あり
3. **詳細＋編集フォーム**: 保存ボタン方式、入力チェック付き
4. **部品カタログ**: 色・文字・角丸・ボタン・バッジ・入力・表などを一覧表示

データは JSON から読み込み、アプリ実行中はメモリ上で保持する（再読み込みで初期状態に戻る）。

## 6. AI にルールを守らせる仕組み（3層＋色チェック）

1. `CLAUDE.md` — AI が最初に読む説明書（禁止事項の要約）
2. 自社スキル `.claude/skills/designing-keihan-ui/` — 詳細ルールと、土台に足りないものが出たときの確認手順
3. 自動チェック `npm run check:design` — 色の直書き（`bg-blue-500`・`#xxxxxx` 等）、任意角丸（`rounded-[..]`）、`bg-card`＋`rounded-md` の共起を検出

同梱する外部スキル（見本から流用）: `shadcn` / `next-best-practices` / `vercel-react-best-practices`

## 7. 運用

- 持ち主は企画部で一元管理。各アプリでは土台（色・フォント・角丸）を変更しない
- 足りないものはこのリポジトリへの要望として集め、企画部が反映する
- AI 用ルールにも「土台を独断で変えず、必要ならユーザーに確認」と明記する
