# 京阪工技社 デザインシステム（業務アプリひな形）

社内の業務用ウェブアプリ（管理画面・業務ツール）を、会社のブランドに沿った見た目で素早く作るための**ひな形**です。
AI（Claude Code）と一緒に作ることを前提に、AI 向けのルール集も入っています。

京阪工技社のデザインシステムは、用途ごとにリポジトリを分けています。

| リポジトリ          | 用途                                         |
| ------------------- | -------------------------------------------- |
| `keihan-ds-webapp`  | 業務アプリ用（このリポジトリ）               |
| `keihan-ds-website` | ウェブページ（LP・社外向けページ）用（予定） |

## 何が入っているか

| 画面           | URL                     | 用途                           |
| -------------- | ----------------------- | ------------------------------ |
| ダッシュボード | `/dashboard`            | 件数・金額のまとめとグラフ     |
| 受注案件 一覧  | `/orders`               | 表＋検索・絞り込み             |
| 受注案件 詳細  | `/orders/ORD-2026-0001` | 編集フォーム（保存ボタン方式） |
| 部品カタログ   | `/catalog`              | 色・文字・ボタンなどの見本帳   |

見本データ（受注案件）は架空です。自分の業務に合わせて作り変えてください。

## 動かし方

```bash
npm install
npm run dev
```

ブラウザで `http://localhost:3000` を開きます。

## 新しいアプリを始めるとき

1. このリポジトリをコピー（テンプレートとして複製）する
2. `lib/brand.ts` の `appName` をアプリ名に変える
3. `data/` と `lib/schema.ts` を自分の業務のデータに作り変える
4. 画面は `app/(app)/` に追加する。部品は `/catalog` にあるものを使う

## このデザインシステムのポイント

### 1. 「共通の土台」と「使い方ルール」の2段構え

- **共通の土台**: 色・フォント・角丸・ロゴ。会社として統一するもので、ウェブページ用とも同じ値を使います
- **使い方ルール**: 土台をどう使うか。業務アプリ用とウェブページ用で別々に決めます（このリポジトリは業務アプリ用）

土台の値は `app/globals.css` の1か所にまとめてあり、画面や部品はすべてそこを参照します。
値を1か所直せば、アプリ全体の見た目がそろって変わります。

### 2. 色は「役割」で使う

色は `#0056A8` のような色番号ではなく、「メイン」「削除・エラー」のような**役割の名前**で指定します（例: `bg-primary`）。

| 役割           | 色                                 | 使いどころ                     |
| -------------- | ---------------------------------- | ------------------------------ |
| メイン         | 青 `#0056A8`（会社HPのブランド青） | 主ボタン・リンク・選択中の項目 |
| 削除・エラー   | 赤 `#E60012`（会社HPの赤）         | **削除ボタンとエラー表示だけ** |
| 情報           | 水色 `#0A9EDB`（会社HPの水色）     | お知らせ・「受付」の状態       |
| 成功           | 緑 `#177A42`                       | 「完了」の状態                 |
| 注意           | 黄 `#F2A900`                       | 「遅延」の状態・注意を促す表示 |
| ページの地・面 | 薄いグレー `#F4F6F9` ＋ 白いカード | 背景と、内容をのせるカード     |

- **赤は目立たせるために使いません。** 業務アプリで赤を見たら「消える・間違っている」と分かるようにするためです
- 状態の色は4つに固定しています（受付＝水色、作業中＝青、完了＝緑、遅延＝黄）。遅延も赤ではなく黄で表します
- 文字と背景の組み合わせは、読みやすさの国際基準（WCAG AA：本文はコントラスト 4.5:1 以上）を満たすことをテストで確かめています

### 3. 文字と形

- フォントは、英字・数字が **Inter**、日本語が **Noto Sans JP**
- 表の数字は桁がそろう等幅数字にし、金額などは右寄せにします
- 角の丸みは **6px** を基準に、部品の大きさに応じて4段階（sm・md・lg・xl）で使い分けます
- ライトモード（明るい画面）のみです

### 4. 画面づくりの決まりごと

- **編集は「入力 → 保存ボタン」で確定します。** 入力しただけで自動保存される方式にはしません。金額や納期の誤変更を防ぐためです
- 保存せずに画面を離れようとすると（リンク・ブラウザの「戻る」・タブを閉じる・再読み込み）、確認を出します
- 入力の間違いは、入力欄のすぐ下に理由を表示します。全角数字やカンマ付きの数字（例: `１２，０００`）はそのまま受け付けます
- 検索結果が0件のときは、真っ白にせず「条件に一致する案件がありません」と「条件をクリア」ボタンを出します
- **パソコン優先**です。タブレット（幅 768px）でも崩れないようにし、横に長い表は表だけを横スクロールさせます
- 部品（ボタン・入力欄・表など）は shadcn/ui という部品集から追加したものを使い、自作しません。見本は `/catalog`（部品カタログ）で確認できます

### 5. AI にもルールを守らせる仕組み

AI（Claude Code）が作る画面もルールからずれないよう、4つの仕組みを入れています。

| 仕組み                           | 役割                                                           |
| -------------------------------- | -------------------------------------------------------------- |
| `CLAUDE.md`                      | AI が最初に読む説明書。禁止事項の要約                          |
| 自社スキル `designing-keihan-ui` | 画面を作るときの詳しいルールと、足りないものが出たときの手順   |
| `npm run check:design`           | 色番号の直書き（`bg-blue-500` など）や角丸のズレを自動で検出   |
| `npm run test`                   | ブランド色の値と、文字の読みやすさ（コントラスト）を自動で検証 |

### 6. 土台は企画部が管理する

- 色・フォント・角丸（`app/globals.css`）は**企画部が一元管理**しています。各アプリで勝手に変えないでください
- 色や部品が足りないときは、企画部に要望を出してください。AI にも「土台を独断で変えず、必要なら確認する」ように指示しています

詳しくは [設計書](docs/superpowers/specs/2026-09-25-keihan-design-system-design.md) を参照してください。

## チェックコマンド

| コマンド               | 内容                                               |
| ---------------------- | -------------------------------------------------- |
| `npm run test`         | テスト（色のコントラスト＝読みやすさの検証を含む） |
| `npm run check:design` | 色の直書き・角丸のズレを検出                       |
| `npm run lint`         | コードの書き方チェック                             |
| `npm run build`        | 本番用にビルド                                     |

## 公開（デプロイ）

公開先は **Vercel** です。GitHub のリポジトリを Vercel に接続すると、設定を変えずに `next build` で公開されます。
データは今は見本の JSON をメモリに持っているだけなので、公開しても編集内容は保存されません（再読み込みで元に戻ります）。
